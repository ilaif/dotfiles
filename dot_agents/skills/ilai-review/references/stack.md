# Reviewing a stack

When Ilai asks for "the stack" (or the PR body has a stack table), review every layer in one pass. Learned on a 13-PR stack.

1. **Snapshot every layer**: number, base ← head, size, open threads, CodeRabbit check. Fetch each head as `pr-<N>`; a layer's own diff is `git diff pr-<prev>...pr-<N>` (three dots, so an upper layer not rebased on the lower head still shows only its own commits; check with `git merge-base --is-ancestor`; the bottom layer: `origin/main...pr-<N>`). Done when every layer has a head SHA and its own diff command.
2. **One brief, many reviewers**: write the shared brief to the scratchpad. It holds the layer order, the diff commands, the ticket's recorded decisions and the lenses. Spawn one `sonnet` reviewer per 1–3 layers, grouped to roughly 1.5–3.5k changed lines each; give the deletion layer its own reviewer, which greps every deleted name across the whole repo. Read the bottom (wiring) layer yourself. Done when every layer has a reviewer or is read by you.
3. **Verify as reports land**: check each finding at its layer head, and record kept and dropped findings in a scratchpad `FINDINGS.md` with `file:line` per layer. A pattern that recurs across layers (e.g. a shared reader searching a column that lists fill with a category word) is one question, raised on the layer that introduced it, and the others link to it.
4. **One artifact for the stack**: a layer table, one diagram of a single request through the shared parts, findings as cards labelled with their PR, and a nit table. Set `meta.sha` to the top layer's head, which holds every file, and take `<Src>` lines at that head. The verifier's "sha isn't on any remote branch" ✗ is a false alarm when `git ls-remote origin refs/heads/<top branch>` returns that SHA.
5. **Map to diff lines per layer**: an inline comment's line must be an *added* line in that layer's own diff at its head (check the `-U0` hunk ranges). A finding on an untouched line goes in that PR's review body.
6. **Post per layer**: a layer with inline comments gets a Comment review, then a one-line approval if Ilai asked for one. A layer with none gets a single review whose body carries its note, as an approval when asked. Check inline counts with `gh api --paginate repos/<o>/<r>/pulls/<N>/comments`: without `--paginate`, bot comments fill page one and the count reads 0.
7. **One DM** for the whole stack, in English (step 8's rule): link the bottom layer's review and the artifact, list the questions with their PR numbers, and name the one follow-up worth fixing.
